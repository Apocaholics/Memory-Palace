# План імплементації: тренажер палацу пам'яті. Ітерація 1

Статус: **підтверджено** користувачем 2026-10-24.
Джерела: [намір](../intent/memory-palace-cards.md), [специфікація ітерації 1](../spec/iteration-1.md) (обидва підтверджено 2026-10-24). Рішення звідти тут не переглядаються. Посилання виду «§3.5» ведуть на розділи специфікації, «КП-7» означає пункт 7 розділу 12 «Критерії приймання».

## Огляд

Статичний сайт на HTML, CSS і ES-модулях без залежностей. Логіка складається з трьох чистих модулів (`cards`, `session`, `storage`), які тестуються в Node. До них додаються `ui.js` (DOM) і `main.js` (склейка). План іде вертикальними зрізами: спершу основа, потім екрани в порядку потоку користувача, кожен разом зі своїми переходами в `reduce` і тестами до них. Після кожної задачі сайт відкривається без помилок, а `npm test` зелений. Наскрізні речі (збереження, клавіатура, wake lock) йдуть після повного циклу. Тоді вони вбудовуються в уже готовий потік і нічого в ньому не ламають.

## Архітектурні рішення плану

Ці рішення уточнюють специфікацію на рівні реалізації і не змінюють її поведінки.

1. **`reduce` лишається чистою.** `id` і `createdAt` для нової сесії генерує `main.js` і передає в дії: `start({ order, id, createdAt })`. Так тести `session.js` детерміновані, а сам перехід відповідає таблиці §4.3.
2. **`reset` повертає `null`.** Відсутність сесії й так означає «Старт» (§4.2). `ui.render(null)` показує екран «Старт».
3. **Карти перевірки й розкладки рендеряться заново.** Поки карта закрита, її лице не потрапляє в DOM навіть прихованим елементом. Це потрібно для КП-5 і §5 («у DOM є лише поточна карта»).
4. **Колір масті береться з коду.** Поруч із `formatCard(code) → "Q♣"` з'являється `isRed(code)`. `ui.js` ставить клас `red`, а символ масті показується завжди (§3.7).
5. **Підтвердження «Нова колода» через `<dialog>`, а не `confirm()`.** У нативному `confirm()` не можна задати кнопки «Так» і «Скасувати», яких вимагає §5.
6. **Клавіатура натискає справжню кнопку.** Обробник клавіш у `ui.js` знаходить кнопку, що відповідає клавіші, і клікає її, лише якщо вона видима й не вимкнена. Так правило «клавіші працюють лише там, де кнопка видима й активна» (§3.7) виконується автоматично, і другого шляху до дій немає.
7. **Слухачі `onTransition(prev, next)` з'являються в Т8.** Першими слухачами стають збереження сесії і wake lock (Т10). Це та сама точка розширення, яку §13 відводить під таймери ітерації 2.
8. **Ідентифікатор сесії лише через `crypto.randomUUID()`, як у §4.2, без запасного варіанта (Р1).** Цей API доступний лише в безпечному контексті (HTTPS або `localhost`). Тому локально застосунок перевіряється на `http://localhost:8000`, а реальний телефон під'єднується лише до опублікованого сайту на GitHub Pages (Т11). Команда §7 з `--bind 0.0.0.0` для телефона в цьому плані не використовується.

## Definition of done (для кожної задачі)

Задача вважається готовою, коли виконано всі її критерії приймання і цей стандартний список:

- [ ] `npm test` зелений. Нова логіка покрита тестами, які падають без зміни (§10, §11).
- [ ] У `package.json` немає залежностей, у коді немає звернень до мережі, CDN чи зовнішніх шрифтів (§11).
- [ ] `cards.js`, `session.js`, `storage.js` не звертаються до DOM; DOM змінюється лише в `ui.js` (§9).
- [ ] Тексти інтерфейсу українською й лежать в одному об'єкті в `ui.js`; ідентифікатори англійською (§9).
- [ ] Якщо задача змінює інтерфейс: агент відкриває `http://localhost:8000` (`python -m http.server 8000`) у вбудованому браузері, і консоль без помилок; перевірено в емуляції телефона 360 px (без горизонтальної прокрутки, кнопки ≥ 48×48 px) і на ширині ноутбука (§3.7, §11, Р4).
- [ ] Немає мертвого коду, налагоджувального виводу й змін поза межами задачі.
- [ ] Перед комітом прогнано `npm test`; зміна закомічена одним локальним комітом у `main` на задачу. Push лише з окремого дозволу користувача (Р2).

- [ ] Недоступний `localStorage` (метод кидає виняток) не ламає застосунок, він працює без збереження (§4.4, §10).
- [ ] Кнопка «Назад» браузера не змінює стан сесії (§5).

**Критерії приймання:**
- [ ] Усі клавіші з §3.7 працюють на відповідних екранах (КП-10).

## Ризики

| Ризик | Вплив | Як зменшити |
|---|---|---|
| `crypto.randomUUID()` і Screen Wake Lock є лише в безпечному контексті. На телефоні за `http://<IP>:8000` (§7) `randomUUID` відсутній, і «Нова колода» впаде | Середній: реальний телефон до Т11 недоступний, проблеми мобільних браузерів виявляться пізно | Р1: свідомо без запасного `id`. До Т11 телефон лише емулюється у вбудованому браузері (360 px, мобільний user agent, дотик); локально лише `localhost`; Т12 перевіряє реальний телефон. Т11 можна зробити раніше, якщо користувач захоче |
| ES-модулі не працюють через `file://` | Низький | Завжди відкривати через `python -m http.server` (§7) |
| Абсолютні шляхи зламають сайт на GitHub Pages у підкаталозі | Середній | Т2: лише відносні шляхи, перевірка з підкаталогу |
| Лице наступної карти випадково опиниться в DOM (прихований елемент, атрибут, `title`) | Високий (суть тренажера) | Рішення 3; ручна перевірка DOM у Т5 і Т12 |
| `Backspace` чи `Пробіл` мають у браузері власну дію (прокрутка, клік по кнопці у фокусі) | Низький | Т9: `preventDefault` для обслуговуваних клавіш, критерій про подвійне спрацювання |

## Ухвалені рішення

Питання, що впливали на план, закрито з користувачем 2026-10-24:

- **Р1. Ідентифікатор сесії:** лише `crypto.randomUUID()`, без запасного варіанта на `getRandomValues`. Наслідок: реальний телефон працює лише з опублікованим сайтом (HTTPS).
- **Р2. Коміти:** один локальний коміт у `main` на задачу, перед ним `npm test`. Push лише з окремого дозволу.
- **Р3. GitHub Pages:** окрема задача Т11 наприкінці плану, перед прийманням. Репозиторій і Pages налаштовує користувач, push робиться з окремого дозволу.
- **Р4. Ручна перевірка:** агент перевіряє кожну UI-задачу у вбудованому браузері (емуляція телефона 360 px і ширина ноутбука). Користувач проходить цикл на ноутбуці на контрольній точці 2 і на реальному телефоні на контрольній точці 4.
- **Список задач** ведеться в цьому файлі, а не в `tasks/todo.md`. Під час реалізації `/build` треба спрямувати на `docs/plan/iteration-1.md`.

Відкритих питань немає.
